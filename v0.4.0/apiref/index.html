AdaptiveCrossApproximation.assemble — Function
assemble(op, testspace, trialspace; tree=..., quadstrat=..., kwargs...)

Assemble a hierarchical matrix with automatic tree-based blocking.

High-level convenience function that automatically constructs a hierarchical clustering tree and assembles the complete HMatrix with near and far-field blocks. This is the recommended entry point for most applications.

Arguments

  • op: Operator/kernel for matrix entry evaluation

  • testspace: Test space (row basis/points)

  • trialspace: Trial space (column basis/points)

  • tree: Hierarchical tree structure. Auto-generated from AdaptiveCrossApproximation.defaulttreebackend() if not provided: a H2Trees.TwoNTree when only H2Trees.jl is loaded, or a k-means clustered tree when ParallelKMeans.jl is loaded alongside it.

  • treekwargs: Keyword arguments forwarded to the automatic tree construction (e.g. minvalues, numberofclusters for the k-means backend); ignored if tree is given explicitly.

  • quadstrat: Quadrature strategy, matching BEAST.assemble's keyword of the same name. Defaults like BEAST.defaultquadstrat(op, testspace, trialspace) for BEAST operators (via the ACABEAST extension).

  • nearquadstrat: Quadrature strategy for near-field (dense) blocks. Defaults to quadstrat.

  • farquadstrat: Quadrature strategy for far-field (compressed, admissible) blocks. Defaults to tofarquadstrat(quadstrat), which strips singular-quadrature handling since far blocks are always well-separated.

  • kwargs...: Additional parameters passed to HMatrix:

    • tol: Convergence tolerance (default 1e-4); also governs every later recompression of the hierarchical arithmetic
    • maxrank: Maximum rank for compression (default 40)
    • compressor: ACA-style compressor. The default is selected by defaultcompressor(op, testspace, trialspace; tol) and is usually ACA.
    • isnear: Admissibility predicate (default isnear())
    • spaceordering: Space ordering strategy (default PreserveSpaceOrder())
    • ntasks: Number of parallel assembly tasks (default Threads.nthreads())
    • verbose: Enable progress output (default true)

Returns

  • HMatrix: Assembled hierarchical matrix

Notes

Requires H2Trees.jl to be loaded for automatic tree generation. If providing a custom tree, ensure it implements the tree interface expected by HMatrix assembly. The two-space call uses general assembly even when testspace === trialspace. For a transpose-symmetric operator, use assemble(op, space; kwargs...) to select symmetric assembly explicitly. For operators whose matrix is cheap to build directly and never benefits from low-rank compression (e.g. BEAST's local operators Identity/NCross), the ACABEAST extension adds a more specific assemble method that bypasses tree construction and ACA entirely, calling BEAST.assemble directly.

Examples

# With BEAST boundary integral operators
hmat = AdaptiveCrossApproximation.assemble(op, testspace, trialspace; tol=1e-5, maxrank=100)
y = hmat * x  # Efficient matrix-vector product

assemble(op, space; tree=..., quadstrat=..., kwargs...)

Assemble a transpose-symmetric H-matrix on one space. Automatic tree construction builds one shared cluster tree. With an explicit tree, only its test cluster tree is used for both axes.

The operator and any custom isnear predicate must be transpose-symmetric; this is a caller-supplied assumption and is not checked. Opposite off-diagonal blocks use a transpose, without complex conjugation. Diagonal near blocks are assembled in full and symmetrized. Each unordered far-field pair is compressed once with the configured compressor.

Accepts the tree, quadrature, compression, ordering, and ntasks keywords of the two-space overload. The call assemble(op, space, space) uses general assembly. BEAST local operators such as Identity and NCross are assembled directly.

Examples

hmat = AdaptiveCrossApproximation.assemble(op, space; tol=1e-5)
hmat = AdaptiveCrossApproximation.assemble(op, space; tree=tree, tol=1e-5)

AdaptiveCrossApproximation.AdaptiveCrossApproximation — Module
AdaptiveCrossApproximation

Adaptive Cross Approximation (ACA) algorithms for hierarchical low-rank matrix compression.

Provides standard and incomplete adaptive cross approximation algorithms optimized for boundary integral operators and other kernel-based matrices. Key features:

  • ACA: Standard adaptive cross approximation selecting pivots by alternating rows/columns
  • IACA: Incomplete variant for geometric pivoting in hierarchical matrix construction
  • HMatrix: Hierarchical matrix representation combining dense near-field and low-rank far-field blocks
  • Pivoting strategies: Maximum value, geometric (Leja, Fill Distance, Mimicry), random sampling
  • Convergence criteria: Frobenius norm estimation, random sampling, extrapolation, combined criteria
  • Kernel matrices: Support for BEAST boundary integral operators and point-based kernels

Main API

Compressors:

  • ACA: Standard row-first variant
  • ACAᵀ: Column-first variant (dual of ACA)
  • IACA: Incomplete variant for geometric pivoting and hierarchical matrices
  • aca: Convenience function for matrix compression

Hierarchical matrices:

  • HMatrix: Hierarchical matrix type
  • AdaptiveCrossApproximation.assemble: Automatic assembly with tree-based blocking
  • nearmatrix, farmatrix: Extract system components

Pivoting strategies:

  • MaximumValue: Partial pivoting (largest absolute value)
  • Leja2: Modified Leja point selection
  • FillDistance: Geometric fill distance minimization
  • MimicryPivoting: Distributional mimicry without full matrix access
  • TreeMimicryPivoting: Tree-aware variant for H²-matrices

Convergence criteria:

  • FNormEstimator: Frobenius norm-based stopping (ACA and IACA paths)
  • FNormExtrapolator: Extrapolation-enhanced convergence detection
  • PhaseExtrapolator: Multi-phase extrapolation for geometric pivoting
  • RandomSampling: Random sampling-based convergence

Kernel matrices:

  • AbstractKernelMatrix: Interface for lazy matrix entry evaluation
  • PointMatrix: Point cloud kernel matrices
  • BEASTKernelMatrix: BEAST boundary integral operator matrices

Example

using AdaptiveCrossApproximation

# Compress a matrix with default settings
U, V = aca(M; tol=1e-4, maxrank=50)
approx = U * V

# Or build an HMatrix with automatic tree-based blocking
hmat = AdaptiveCrossApproximation.assemble(operator, testspace, trialspace)
y = hmat * x  # Matrix-vector product

See also

  • BEAST.jl for boundary integral operators
  • H2Trees.jl for hierarchical clustering
  • H2Trees.jl for hierarchical block partitioning

AdaptiveCrossApproximation.ACA — Method
(aca::ACA{FullPivoting,FullPivoting,FNormEstimator})(A, maxrank=min(size(A)...); sampled=false)

Compute a full-pivoting ACA factorization of the dense matrix A, in place.

At each step, selects the entry of largest absolute value in the remaining (unfactored) submatrix as the next pivot, swaps it onto the diagonal, and eliminates it with a rank-1 Schur update — the direct, whole-matrix counterpart of MaximumValue-based ACA. Used wherever the whole matrix is available up front, e.g. as the CPU reference for the batched GPU kernel in the ACACUDA extension.

With sampled=true, stops when norm(residual)/norm(original) * sqrt(s/(s-rank)) <= tol, where s is the sampled column count. This estimates the full block's relative Frobenius error assuming representative remaining residual entries and a far field much larger than the sample. Pivot rows cancel because all rows are sampled. The default sampled=false uses the ordinary relative Frobenius criterion.

Arguments

  • A::AbstractMatrix{T}: matrix to factor; overwritten in place with the working Schur-complement state.
  • maxrank::Int: hard cap on the number of pivots.
  • sampled::Bool: rescale the residual of representative column samples.

Returns

  • rank::Int: number of pivots selected (≤ maxrank).
  • rowpivots::Vector{Int}, colpivots::Vector{Int}: selected row/column indices, in selection order.

(aca::ACA)(A, colbuffer, rowbuffer, rows, cols, rowidcs, colidcs, maxrank)

Compute ACA approximation with preallocated buffers (main computational routine).

Fills colbuffer and rowbuffer with low-rank factors U and V such that A[rowidcs, colidcs] ≈ U * V. Previously computed rank-one terms are subtracted from every newly sampled row and column.

  • rowidcs::Vector{Int}: Global row indices of the block to compress

Returns

  • npivot::Int: Number of pivots computed (≤ maxrank). The approximation is A[rowidcs, colidcs] ≈ colbuffer[:, 1:npivot] * rowbuffer[1:npivot, :]

HMatrix(operator, testspace, trialspace, tree; kwargs...)

Assemble a hierarchical matrix approximation of an operator on test and trial spaces.

Arguments

  • operator: bilinear form or kernel operator used for matrix entry evaluation
  • testspace: test space used for row indexing
  • trialspace: trial space used for column indexing
  • tree: hierarchical clustering/tree structure controlling block partitioning
  • tol: compression tolerance (default 1e-4). It is stored with the matrix and governs every later recompression of the hierarchical arithmetic.

An HMatrix containing assembled near and far interactions.

Use this constructor as the main entry point when you already have a tree. For a convenience entry point, use assemble. This two-space constructor uses general assembly even when the spaces are the same object. Use HMatrix(operator, space, tree; kwargs...) for a transpose-symmetric operator.

AdaptiveCrossApproximation.HMatrix — Method
HMatrix(operator, space, tree; kwargs...)

Assemble a transpose-symmetric H-matrix on one space. Only testtree(tree) is used for both axes. The operator and any custom isnear predicate must be transpose-symmetric; this assumption is not checked. Complex symmetric operators use a transpose, without conjugation, for the opposite block.

Each terminal near pair is stored as one dense block. Far blocks use the configured compressor once per unordered pair and share their factors with the transposed logical block. Diagonal near blocks are assembled in full, then made symmetric by copying their upper triangles into their lower triangles.

Compression, assembly-data and ntasks keywords follow the two-space constructor. For automatic tree construction, use assemble(operator, space).

Examples

hmat = HMatrix(operator, space, tree; tol=1e-5)

AdaptiveCrossApproximation._ProductPlan — Type
_ProductPlan(C::HMatrixBlock, A::HMatrixBlock, B::HMatrixBlock; batchrank=128)

Reusable plan for C += α*A*B on hierarchical blocks whose corresponding axes share cluster trees; the terminal partitions may differ. Ranks may change between executions, the partitions may not. It is the kernel of mul!, of the Schur-complement updates of the LU factorization and of the updates in the triangular solves.

The plan has one _ProductGroup per destination terminal of C, which collects every terminal pair of A and B meeting it:

  • dense × dense pairs contribute exact factor slices, or are summed into a dense m × n core once their inner dimensions reach mn/(m+n);
  • a low-rank terminal multiplies the whole hierarchical panel of the other operand at once (_ProductPanel);
  • a low-rank terminal whose rows (or columns) strictly contain several complete destinations is attached to a virtual _ProductNode above them: its product is formed and recompressed once, and the destinations receive a slice of their nearest node;
  • a complete far destination is recompressed directly from the implicit operator C + α*A*B (_ProductOperator) when that is estimated to be cheaper.

Low-rank updates are collected as pending columns, at most batchrank per far destination, and recompressed together with the destination. Buffers belong to the executing task's scratch, so nodes and destinations can run on different tasks; nodes run before the nodes and destinations below them (see _productgraph).

AdaptiveCrossApproximation._sketchrecompression! — Method
_sketchrecompression!(S, m, n, guess, qcap, scratch, atol, rtol, maxrank)

Randomized spectral-norm recompression of an implicit m × n operator S (adaptive randomized range finder of Halko, Martinsson & Tropp 2011, Alg. 4.2, with blocked sampling). S only needs to apply itself to a block of vectors (_sketchapply!) and to project onto a basis (_sketchproject!), so sums of factors and hierarchical products are never formed explicitly.

The first guess samples build an orthonormal basis Q. Each further block of p = 8 Gaussian samples, projected onto the complement of Q, certifies

‖(I - QQ')S‖ ≤ 10 √(2/π) maxᵢ ‖(I - QQ')S ωᵢ‖

except with probability 10^-p, or is appended to Q. The bound is driven below a tenth of the tolerance and charged against it after the SVD of Q'S (see _recompressionrank). The sampling RNG has a fixed seed, so results are reproducible.

Returns (U, V, info), or nothing if Q would exceed qcap columns; the caller then falls back to a deterministic QR/LQ/SVD recompression.

Hierarchical LU factorization of H in place: the blocks of H are overwritten by the factors, so H no longer represents the original matrix. Every block update is recompressed to H.tol.
